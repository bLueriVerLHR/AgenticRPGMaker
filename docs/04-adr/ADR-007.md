# ADR-007 — Agentic operability & agent-readable docs

## Metadata

- **Status:** accepted
- **Date:** 2026-08-25
- **Author:** user decision (recorded by the Documentation Scribe)

## Status

- **Status:** accepted
- **Supersedes:** none

## Context

The user requires three things for the project to be **agent-operable**:

1. **(a) All-English engineering.** Every engineering artifact (docs, code,
   comments, commit messages, UI strings) is in English. Game **content** text
   (dialogue, item names) is **player data** and is **not** language-restricted —
   it is the game author's content, not engineering.
2. **(b) Agent-readable docs.** Documentation must be structured so an AI agent can
   read it without asking a human — stable headings, machine-checkable status
   fields, valid links.
3. **(c) Agent-operable system.** The tools and system must be operable by agents
   (headless, scriptable interfaces), not only by humans clicking a GUI.

These are hard user requirements on top of the existing engineering rules
(continuous docs, WAL, mandatory logging, mandatory tests).

## Decision

**All-English engineering rule** for all repo artifacts; **game content text
unrestricted** (player data).

**Baseline tier (IN MVP):**

- **`AGENTS.md`** onboarding doc at the repo root: repository layout, WAL rules,
  one-command build/test/lint scripts, where decisions live.
- **Doc structure conventions** (stable headings, machine-checkable status fields)
  applied to every doc.
- **Doc link/status lint enforced in CI.**

**Upper tiers (DESIGN NOW via reserved interfaces, IMPLEMENT LATER, NOT in MVP):**

- **Editor headless CLI** (`create-project` / `add-map` / `set-tile` /
  `place-event` / `export-www`).
- **Runtime headless test mode.**
- **Server control API** (rooms / status / kick over HTTP/CLI, JSON in/out).

These are **reserved as documented seams** — see the seams summary in
[06-architecture.md](../06-architecture.md). They are designed now (so the
architecture does not paint us into a corner) but **must not be implemented
prematurely in the MVP**.

## Consequences

### Positive

- Agents (including future team members and tooling) **onboard without asking** —
  `AGENTS.md` is the entry point.
- Docs are **machine-checkable**: lint in CI catches broken links and invalid
  status fields before merge.
- The reserved seams (headless CLI, runtime headless mode, server control API)
  make **future LLM-direct-editing** and agent-driven operation possible without
  re-architecting later.

### Negative

- Doc conventions add a little **ceremony** (every doc must follow the structure
  and pass lint).
- **Discipline cost:** reserved interfaces must not be implemented prematurely in
  the MVP — scope discipline is required, not optional.
