# ADR-008 — Chunked world streaming: world manifest + map-v1 chunks, save v2

## Metadata

- **Status:** proposed
- **Date:** 2026-08-26
- **Author:** AgenticRPGMaker Bot (engine member proposal; leader to review)

## Status

- **Status:** proposed
- **Supersedes:** none

## Context

The v1 runtime loads **one** `MapData` document at boot (`boot.ts`, `mapUrl | mapData`),
builds one `MapScene`, one collision grid, and saves to a single-`mapId` save document
(ADR-003, save v1). The leader wants a **seamless open-world** demo: a world larger than
one document, loaded without screen transitions, with story state that crosses map
boundaries. Scaling a single map document fails structurally: `width×height` tile
arrays grow quadratically (a 1 000×1 000 map ≈ millions of cells in one JSON pay-load),
parse blocks the frame, and per-map `variables`/`switches` cannot express cross-map
story conditions.

Constraints honored (leader decisions, rounds 1–3 of the 2026-08-26 discussion):

- Chunk payloads must stay valid **map-v1 documents**, so the existing editor can
  open every chunk unchanged (editor work is a non-goal for this feature).
- The single-map boot path (`mapData`) and the editor's embedded preview must keep
  working — the world path is additive (`worldUrl`), not a replacement.
- Save must survive chunk eviction: defeated enemies, opened doors etc. must not
  respawn/reset because their chunk left memory.

## Decision

**A `world.json` manifest + one map-v1 document per chunk, streamed by a chunk pool;
global state in the manifest; per-chunk runtime deltas in save v2.**

1. New **world schema v1** (`packages/core/src/schema/world.ts`): manifest only —
   `schemaVersion: 1`, `id`, `name`, `chunkSize`, `grid {cols, rows}`, `chunks`
   (`id`, `file`, `col`, `row`, optional `combatants`), `combatTypes`, `spawn`
   (chunk + tile + direction), `tilesets`, and the **global** `variables` /
   `switches` store. Chunk documents remain untouched map v1; their local
   `variables`/`switches` fields are ignored in world mode (manifest's `global`
   wins — single source of truth).
2. **New save schema v2** (`packages/core/src/schema/save-v2.ts`, v1 untouched):
   `worldId`, `player {chunkId, x, y, direction, hp}`, global `variables` /
   `switches`, and `chunkState { [chunkId]: { defeatedIds: string[] } }`. The
   runtime storage adapter discriminates on `schemaVersion`.
3. **Runtime chunk pool** (`WorldScene`): prefetch radius 1, evict radius 2, LRU;
   chunk fetch → parse+validate **in a Web Worker** (main-thread fallback where
   workers are unavailable); eviction deferred while the interpreter is executing
   a page against that chunk.
4. **Cross-boundary continuity**: integer pixel offsets only; one owner per
   boundary row (col/row = floor-div by `chunkSize`); stepping into a
   not-yet-resident target chunk blocks the step with a `warn` log (unreachable in
   practice thanks to prefetch radius 1).
5. Boot keeps `mapUrl`/`mapData` exactly as today; `network` combined with
   `worldUrl` logs a warning and is unused (multiplayer in world mode is out of
   demo scope).

## Consequences

### Positive

- Editor compatibility by construction (chunk = map v1); zero editor changes.
- First paint is decoupled from world size: only the spawn chunk gates player
  release; the demo's acceptance budget (≤300 ms title paint, no >33 ms crossing
  frame) is measurable, not vibes.
- Story state (globals + defeated enemies) survives eviction and reloads — the
  seamlessness covers both space and restart.
- The worker seam doubles as the future asset/streaming hot path; the manifest is
  the natural place for later worlds (biomes, weather, more combat types).

### Negative

- Two schemas to maintain (world v1, save v2) alongside v1 — versioning discipline
  and changelog hygiene become mandatory.
- Chunk-boundary edge cases (NPC facing across the seam, projectiles crossing
  chunks, spawn-adjacent interact) need dedicated unit tests; they are the classic
  source of "works until you cross a border" bugs.
- Save v2 diverges from v1 → storage adapter needs a version discriminator and both
  paths keep passing tests.
- Workers in the portable `www` bundle need build-tool care (esbuild worker
  bundling) and a fallback — weak-device surface grows slightly.

## Implementation notes (2026-08-26, feat/open-world-demo)

Implemented as proposed with these verified deltas:

- `world` v1 gained `intro: EventCommand[]` and
  `worldCombatant.onDefeatSwitch?: string`; `world.spawn.x/y` are **global**
  tile coordinates.
- `ChunkStore.onLoaded`/`onEvicted` are writable fields (late-bound wiring);
  `WorldScene.exit()` is a backgrounding pause with teardown in `dispose()`.
- Golden-path E2E (`packages/runtime/e2e/run-world-e2e.mjs`) covers the full
  acceptance path (14/14 steps); see docs/09 §13.
