# ADR-009 — On-map real-time action combat (grid-step Zelda-minimal)

## Metadata

- **Status:** proposed
- **Date:** 2026-08-26
- **Author:** AgenticRPGMaker Bot (engine member proposal; leader to review)

## Status

- **Status:** proposed
- **Supersedes:** none

## Context

Combat was an explicit MVP non-goal
([07-mvp-plan.md](../07-mvp-plan.md) §9.2); no battle concept exists anywhere in
the engine. The open-world demo (2026-08-26 leader decisions) requires **real-time
action combat on the map** — the leader chose on-map action over a turn-based
battle scene (the cost: new AI, real-time resolution, hit/knockback/death flows)
while keeping **grid-step movement** (tile steps, 0.15 s per step). The two
choices together define a Zelda-minimal combat skeleton: attack resolves on the
facing tile, enemies step on the same grid and deal contact damage.

Scope guards from the same discussion: two enemy types, one-shot kills, no
respawn, no inventory/equipment, death returns the player to spawn without
losing story progress. Combat data must live in the **world layer** (ADR-008),
never in map-v1 documents, so the editor stays untouched.

## Decision

**Combat is a set of on-map systems in `WorldScene`, driven by world-layer data
and the existing input/event bus:**

1. **Verbs**: confirm key = sword swing toward the facing tile, 0.35 s cooldown,
   1 damage to any combatant on that tile; contact: a chasing enemy whose next
   step target is the player's tile deals `damage` instead of entering —
   strict-overlap semantics from the existing movement code are preserved.
2. **Player survivability**: 3 HP (hearts in HUD), 0.5 s i-frames (blink) after a
   hit, knock-step 1 tile back onto a free tile.
3. **Enemy behaviors** (from `world.combatTypes`): `slime` = chase (dx-first dumb
   steering on the grid, `speed` steps/s); `turret` = stationary ranged, fires an
   8-tile projectile every 2.4 s (projectiles die on solid tiles or on hit).
   Spawn positions come from the chunk's `combatants` list; already-defeated ids
   (save `chunkState[chunkId].defeatedIds`) are never spawned.
4. **Death flow**: HP → 0 ⇒ fade out → respawn at `world.spawn` (full HP) ⇒ fade
   in. Globals and chunk deltas persist (ADR-008) — no Game Over screen: the demo
   is a 15-minute narrative slice; punishing replays is out of scope.
5. **Freeze gate**: title / CG / dialogue-open states suspend enemy AI,
   projectiles and contact checks. The world is globally at rest during narrative
   moments (player input is already gated the same way).

## Consequences

### Positive

- Coherent with grid movement: no pixel-level hitboxes, no physics — AI, attack
  and damage all resolve on the same tile grid the movement code already uses;
  every rule is unit-testable as pure functions.
- Small surface: two behaviors, one verb, one projectile — realistic for a
  vertical slice under the WAL testing gate.
- Combat never touches map v1 or the editor; world-layer data can grow combat
  types later without schema rework.

### Negative

- "Real-time action" is constrained by the grid: no diagonals, no collision
  pushing, no attack combos — players expecting a modern action feel will notice
  the retro constraint (accepted by the leader: grid-step movement was chosen for
  exactly this scope).
- Interleave hazards (dialogue during a chase, CG mid-projectile) all funnel into
  the freeze gate — it must be exhaustive or enemies will hit players during
  cutscenes (pre-mortem finding B1).
- Dumb steering means enemies can hug walls; acceptable for the two demo types,
  a real pathfinder is future work.
- Turret projectiles crossing chunk boundaries need boundary tests (they live only
  while their owner chunk is resident; radius-2 eviction guarantees they expire
  before their chunk does).

## Supersedes

None.

## Implementation notes (2026-08-26, feat/open-world-demo)

Implemented as proposed with these verified deltas:

- `world` v1 gained `intro: EventCommand[]` and
  `worldCombatant.onDefeatSwitch?: string`; `world.spawn.x/y` are **global**
  tile coordinates.
- `ChunkStore.onLoaded`/`onEvicted` are writable fields (late-bound wiring);
  `WorldScene.exit()` is a backgrounding pause with teardown in `dispose()`.
- Golden-path E2E (`packages/runtime/e2e/run-world-e2e.mjs`) covers the full
  acceptance path (14/14 steps); see docs/09 §13.
