# ADR-010 — CG presentation layer & minimal WebAudio engine

## Metadata

- **Status:** proposed
- **Date:** 2026-08-26
- **Author:** AgenticRPGMaker Bot (engine member proposal; leader to review)

## Status

- **Status:** proposed
- **Supersedes:** none

## Context

The demo requires **full-screen CG playback** (opening/ending cutscenes) and
atmosphere. Today the interpreter can show text (`showText`) and *request* sound
(`playSound` publishes a bus event that the runtime currently only logs — audio was
an MVP non-goal, [07-mvp-plan.md](../07-mvp-plan.md) §9.2). The leader re-opened
audio for the demo (decision 15: minimal engine), chose **static CG images +
presentation cues** over real video (no codec burden, portable per
[08-compatibility-checklist.md](../08-compatibility-checklist.md)) and a **title
screen** that doubles as the browser autoplay unlock (decision 16).

## Decision

**Cgs are interpreter-scripted presentations of full-screen stills; audio is a
procedural WebAudio layer; both hang off the existing event bus.**

1. **New interpreter commands** (core publishes events, never renders or plays —
   same discipline as `showText`): `showCg <imageRef> [mode=cover|fit]`,
   `fadeOut <color> <ms>`, `fadeIn <ms>`, `letterbox <on|off>`, `bgm <ref>`,
   `sfx <ref>`, `endCg`. Event pages therefore script entire cutscenes as data
   (ADR-003) — e.g. fade → image → letterbox → lines → endCg.
2. **Renderer**: add `registerTexture(id, url)` + `drawTexture(id, x, y, w, h,
   screenSpace)` to the `Renderer` interface, implemented in both WebGL and
   Canvas2D backends; `CgScene` draws the still in screen space (ignoring the
   world camera), fades are full-screen rects, letterbox = top/bottom bars; any
   confirm key skips/advances.
3. **Runtime `CgScene` + `TitleScene`** in the existing SceneManager: title shows
   "press any key", which also resumes the `AudioContext` (user-gesture
   requirement); CgScene hosts the presentation commands; `WorldScene` freezes
   (ADR-009) while they run.
4. **Minimal audio manager** (`packages/runtime/src/audio.ts`): one
   `AudioContext`; BGM = tiny note sequencer on `OscillatorNode` (looped, per-ref:
   `title`/`village`/`wilds`/`fortress`/`ending`); SFX = synthesized one-shots
   (coin, sword, hit, defeated, door, save). All assets are code — no files in
   `audio/` — and the `bgm`/`sfx` refs are stable identifiers, so real audio files
   can replace synthesis later without touching event data.
5. **Null-safety**: headless/jsdom (tests) inject a fake context; blocked
   autoplay logs `warn` and degrades to silence; lifecycle events (`info`) per
   the logging rules.

## Consequences

### Positive

- Cutscenes are data (versions, copies, and tests like every other document), not
  code — the E2E gate can assert the whole opening CG deterministically.
- Zero binary assets for the demo: CG stills are generated placeholders, audio is
  synthesized — nothing to ship, nothing to license, total package stays tiny.
- The `bgm`/`sfx` ref seam means real authoring later (editor, real assets) is an
  additive change; the renderer's `drawTexture` is the same primitive a future
  portrait/立绘 layer reuses.

### Negative

- Synthesized audio is placeholder-grade (square/sine loops) — atmosphere will
  feel provisional; accepted for the demo, real audio is follow-up work.
- CG stills need loading latency management (preload spawn-side); a full-screen
  image appearing late would break the presentation — hence `registerTexture`
  ahead of first use + `CgScene` readiness check rather than fire-and-forget.
- Two more runtime scenes (Title, Cg) and a new renderer API expand the testing
  matrix on both backends.
- Re-opening an MVP non-goal sets precedent; scope is pinned by this ADR to
  BGM+SFX only (no volume/mixer/streaming — explicitly out).

## Supersedes

None.
