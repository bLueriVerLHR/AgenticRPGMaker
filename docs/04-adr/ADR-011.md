# ADR-011 — Multi-area worlds: named area grids + transfer event command

## Metadata

- **Status:** proposed
- **Date:** 2026-08-27
- **Author:** AgenticRPGMaker Bot (engine member proposal; leader to review)

## Status

- **Status:** proposed
- **Supersedes:** none

## Context

ADR-008 shipped a single flat world grid streamed through ChunkStore. Two
leader requests from the 2026-08-27 playtest discussion stress it:

1. **On-demand map loading / payload reduction.** World chunks are already
   streamed on demand (prefetch 1, evict 2, worker parse), but tile layers are
   JSON integer arrays — the demo's nine chunks weigh ~970 KB raw (~150 KB
   gzipped). Wire size is the actual lever; the streaming design itself holds.
2. **Houses & rooms** — a door that opens into an interior map. Nothing in the
   current data model expresses "a second, separate map", and the interpreter
   has no command to move the player between maps.

Constraints honored:

- Map payloads stay legal **map-v1 documents** (ADR-003/ADR-008 invariant) so
  the editor keeps opening every chunk unchanged.
- Save v2 (ADR-008 §7) must keep loading existing saves.
- The single-map boot path and editor preview remain untouched.

Full discussion context and the rejected alternatives live in
[docs/10-engine-editor-phase2.md](../10-engine-editor-phase2.md).

## Decision

**Worlds gain named areas — each an independent chunk grid with its own spawn
semantics — and the interpreter gains a `transfer` command that moves the
player between them behind an optional fade transition. Tile-layer wire format
gains an opt-in run-length encoding with plain-array fallback.**

### 1. Area model (world schema v1 → additive v1.x)

```
worldSchema:
  areas: [                                  // NEW, ≥ 1 entries
    {
      id: string                            // "overworld", "house_smith", …
      grid: { cols, rows }                  // per-area grid (interiors are tiny)
      chunks: [ worldChunk ]                // same chunk shape as today
    }
  ]
  spawn: { areaId?, x, y, direction? }      // areaId optional; default = areas[0].id
  combatTypes / global store: unchanged     // stay world-scoped
```

- The existing top-level `grid`/`chunks` migrate **into** `areas[0]`
  ("overworld"); parsing accepts both shapes during a deprecation window
  (flat form = one-area world) so nothing breaks mid-rollout.
- Per-chunk combatant placement continues as-is; interiors declare zero
  combatants, which keeps combat data out of houses without special rules.
- Save v2 adds one optional field: `areaId` (default = first area). Old saves
  load unchanged; no version bump. Boot restores residency around
  `{areaId, x, y}`; per-chunk defeated ids keep working because chunk ids are
  validated unique across all areas (explicit acceptance criteria for the
  schema change).

### 2. Transfer command (interpreter + map-v1 event pages)

```
{ cmd: "transfer", args: ["house_smith", 8, 6] }
{ cmd: "transfer", args: ["overworld", 22, 30, { direction: "down",
    transition: "fade", bgm: "village" }] }
```

Semantics:

- Validates the target area exists and coordinates are in bounds at parse
  time of the executing page (fail fast, same discipline as other commands).
- Runs under the standard freeze gates: ignored while dialogue is open or the
  player is dead (ADR-009 §5.5 family).
- `transition: "fade"` performs fadeOut → swap active area + player position →
  begin fetching target-area resident set → fadeIn. With `"none"` it snaps.
- During the fade-out window the runtime eagerly prefetches the destination
  area's spawn neighborhood, hiding interior load latency entirely.

This deliberately makes doors ordinary events: no new entity type, no editor
entity class, and composition with switches/conditions comes free (a door can
be locked by checking a switch on an earlier page).

### 3. Tile-layer RLE codec (map layer encoding, opt-in)

```
layer.data: number[][]                       // today — stays valid forever
layer.dataRLE?: [value, run][]               // NEW optional sibling
// decode rule: when dataRLE is present, decoded[i] expands runs in order;
// total run length MUST equal width*height (schema-enforced)
```

- Schema-validating both forms costs one branch; generators/encoders choose
  per layer (`dataRLE` when compressible, plain otherwise).
- A spike measures RLE vs binary Uint16 against real generator output before
  implementation lands; the acceptance bar is ≥ 70 % transfer reduction vs
  the current JSON baseline with first-playable ≤ 200 KB gzipped.
- One canonical encoder/decoder lives beside the schema; world generator,
  runtime decoder, and tests share it (no second implementation to drift).

## Consequences

### Positive

- Houses/rooms become authorable with **no new runtime concept**: interiors
  are small areas reusing residency, collision, saves, and rendering verbatim.
- Doors compose with the existing condition/page machinery (locked doors,
  story-gated teleports) without dedicated door entities.
- Payload reduction applies to every future world immediately; measured
  acceptance bar instead of vibes.
- Old saves and old editor exports keep working (optional fields + fallback
  decode).

### Negative

- Areas multiply the states save/restore must reason about (area-scoped
  residency); a careless restore could strand the player referencing another
  area's coordinates — covered by explicit E2E (save inside house → reload).
- The flat→areas migration gives the parser two acceptable shapes during the
  deprecation window — temporary ambiguity that must eventually collapse.
- Transfer-in-fade interacts with the freeze gate and chunk prefetch timing;
  edge-case bugs here manifest as rare one-frame flashes of void texture.
- Editor gains only parameter fields this round; authors hand-type target
  coordinates until a linking tool arrives (accepted scope fence).

## Supersedes

None. Extends ADR-008 streaming with an area dimension; supersedes nothing.
