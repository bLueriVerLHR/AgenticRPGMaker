# Task 07 — Runtime platform-capabilities probe (D21/D23 seam)

| Field | Value |
|---|---|
| **Goal** | A `PlatformCapabilities` probe exists in `packages/runtime` (new `src/platform.ts`) that reports, in one read-only snapshot: renderer backend (WebGL2/WebGL1/Canvas2D or none), input devices (touch / keyboard), storage availability (IndexedDB), and audio support (Web Audio `AudioContext`). `boot()` logs the snapshot at `info` (first-class diagnosability per ADR-002 logging) and the probe is injectable for tests. |
| **Why** | `docs/06-architecture.md` §7 documents a **Platform capability (Strategy / Feature-detect, D21/D23)** pattern — "one runtime, many configurations; browser and JoiPlay are configurations of the same runtime, selected by a thin platform-capability layer." The code only has a renderer-specific probe (`packages/renderer/src/capability.ts`); there is **no runtime-level platform probe** — a WAL violation (docs describe a seam the code does not provide). This is the concrete first step of the multi-backend abstraction the user asked for ("依靠抽象支持更多的后端和系统"). |
| **Approach** | 1. New `packages/runtime/src/platform.ts`: `PlatformCapabilities` interface (`{ renderer: { backend, reason? }, input: { touch, keyboard }, storage: { indexeddb }, audio: { webAudio } }`) + `probePlatformCapabilities(options?)` with an injectable probes object (defaults detected from the environment; `AudioContext`/`indexedDB`/`ontouchstart`/`matchMedia` guards so it never throws in Node or old WebViews). 2. `boot.ts`: probe once and log the snapshot at `info` (mirroring the existing storage-availability log). 3. Keep it dependency-light: reuse `renderer` capability probing only as an optional override; the probe itself uses `canvas.getContext` probes. 4. Unit tests (Vitest) with fake probes; no DOM dependency in Node (all detection wrapped in guards). |
| **Files touched** | `packages/runtime/src/platform.ts` (new), `packages/runtime/src/boot.ts`, `packages/runtime/src/index.ts` (export), `packages/runtime/tests/platform.test.ts` (new) |
| **Acceptance criteria** | `probePlatformCapabilities()` returns a well-typed snapshot with all four sections; runs in Node (no throw) and browser; injectable probes honored; boot log includes `platform` snapshot at info; runtime unit tests green; `pnpm validate`/`doc:lint`/lint/format green. |
| **Status** | done |
