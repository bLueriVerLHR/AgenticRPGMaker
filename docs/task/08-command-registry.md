# Task 08 — Open event command system via a Command Registry

| Field | Value |
|---|---|
| **Goal** | The event command system supports **custom commands**: a `CommandRegistry` (register/build API) seeds the built-in commands and lets games / AI-authored data register extra commands; `commandFromSchema` stays backward compatible (default registry) and unknown commands still fail fast via `UnknownCommandError`. |
| **Why** | Goal axis "增强可定制性（事件命令系统）": RPG Maker's plugin-command model — authors define game-specific commands that the interpreter executes. Today `commandFromSchema` is a closed `switch` (unknown `cmd` → throw). The schema layer is already open (`cmd: z.string().min(1)`, `args: z.array(z.unknown())`), so only the interpreter needs opening. Also serves the data-first authoring path (D24): AI can register game-specific commands and have them validated+executed uniformly. |
| **Approach** | 1. In `packages/core/src/interpreter/commands.ts`: add `CommandFactory = (command: EventCommand) => Command`; add `CommandRegistry` class (`register(cmd, factory)`, `has(cmd)`, `build(command)` — throws `UnknownCommandError` when absent); seed a `defaultCommandRegistry` with the existing six built-ins (extract the bodies of the existing switch cases into factories). 2. `commandFromSchema(command)` becomes `defaultCommandRegistry.build(command)` (unchanged signature/behavior). 3. `packages/core/src/interpreter/interpreter.ts`: `InterpreterDeps.registry?: CommandRegistry` (defaults to `defaultCommandRegistry`); `runEvent` uses `this.registry.build(line)`. 4. Export `CommandRegistry`/`CommandFactory` from the interpreter index. 5. Tests: register a custom command → interpreter runs it and records its effect; unknown command still throws; default registry has the six built-ins; custom registry can *replace* a built-in. |
| **Files touched** | `packages/core/src/interpreter/commands.ts`, `packages/core/src/interpreter/interpreter.ts`, `packages/core/src/interpreter/index.ts`, `packages/core/tests/interpreter/interpreter.test.ts` (or a new `commands-registry.test.ts`) |
| **Acceptance criteria** | Custom command executes through `EventInterpreter` and its effects appear; built-in behavior unchanged (existing interpreter tests green); unknown command still fails fast; typecheck/lint/format/doc:lint/validate green. |
| **Status** | done |
