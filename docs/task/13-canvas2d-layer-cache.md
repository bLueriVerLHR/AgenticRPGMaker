# Task 13 — Canvas2D static tile-layer offscreen caching

| Field | Value |
|---|---|
| **Goal** | The Canvas2D backend (the JoiPlay weak-device path, ADR-002 fallback) stops re-drawing every visible tile each frame: static tile layers render **once** into an offscreen canvas at first draw, then each frame blits the visible region with a single `drawImage`. |
| **Why** | Goal axis "渲染/运行时性能" + "多后端可移植性" (JoiPlay). `drawTileLayer` currently calls `drawImage` **per visible tile per frame** — ~300 draw calls/frame for a 320×240 viewport at 16px tiles — each through the transform stack. Map layers are static at runtime (no runtime layer mutation in the schema), so caching is sound. On weak WebViews this is a measurable CPU/GPU win that scales with map size. |
| **Approach** | 1. `Canvas2DRendererOptions` gains `createCanvas?: (width, height) => CanvasLike` — offscreen-canvas factory (default: `document.createElement("canvas")` when DOM is available; tests inject a stub). 2. Private `tileLayerCache = new Map<string, TileLayerCacheEntry>` keyed by `layer.id`; entry = `{ canvas, cols, rows, tileSize, revision, opacity, budgetOk }`. 3. In `drawTileLayer`: after the existing visibility/binding/source checks, if the layer pixel area exceeds a budget (`MAX_TILE_LAYER_CACHE_PIXELS = 4_000_000`, ~16MB RGBA) fall back to the existing per-tile culled path (huge AI-authored maps must not allocate giant canvases). On cache miss or atlas-revision change, rebuild: draw every non-empty tile into the offscreen context (opacity applied once at build). On hit, blit the visible tile range from the cached canvas in **one** `drawImage` (source rect = visible region px), through the same world transform. 4. Invalidation: entry stores the atlas `getRevision(textureId)`; a changed revision rebuilds (source not ready → skip, next frame builds). 5. **Tests** (canvas2d.test.ts): static layer drawn twice → the main context sees exactly **1** `drawImage` per frame after build (vs N without cache) while the offscreen context saw the N tile draws during build; camera/viewport change still renders the correct region (stub records drawImage source rects); oversized layer falls back to the per-tile path; revision change rebuilds. |

| **Acceptance criteria** | Rendering output is unchanged (existing renderer tests green; new tests prove single-blit-per-frame and fallbacks); runtime/typecheck/lint/format/doc:lint/validate green. |
