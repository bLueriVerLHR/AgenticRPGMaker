# Task 15 — Variable-based page conditions (branching on variables)

| Field | Value |
|---|---|
| **Goal** | Event-page conditions can branch on **variables** (not just switches): a page condition becomes `{ switchId, value }` (existing, unchanged) **or** `{ variableId, op, value }` where `op ∈ eq/ne/gt/gte/lt/lte`. Data-first (D24): AI-authored JSON can express "this page shows when gold ≥ 10". |
| **Why** | Goal axis "改进事件解释器/数据管线" + "增强可定制性". Switches-only conditions are a real data-pipeline gap: dialogue/quest branches keyed on progress numbers (gold, kills, flags-as-counters) are impossible today — the inn owner can greet returning guests via a switch (RPG 101) but cannot react to *how much* gold the player has. This is also the foundation branching dialogue needs (feeds a future showChoices). |
| **Approach** | **Schema** (`schema/map.ts`): widen `eventPageConditionSchema` to `z.union([switchCondition, variableCondition]).nullable()` — the switch branch keeps its exact current shape (`{switchId, value}`); the variable branch is `{variableId: string, op: z.enum(["eq","ne","gt","gte","lt","lte"]), value: number}`. Union discriminates structurally (`"switchId" in condition` vs `"variableId"`), so **existing sample data is untouched**. **Interpreter** (`interpreter.ts`): `evaluateCondition` handles both branches (switch → `getSwitch` equality; variable → compare `getVariable` via `op`). `selectPage` already loops conditions — no change. **Tests**: core — `evaluateCondition` for each op (eq/ne/gt/gte/lt/lte) with true/false cases; `selectPage` picks the variable branch when it holds and falls through otherwise; schema round-trip (`parseMapDocument`) accepts the variable condition and rejects bad `op`. **Sample**: extend the inn owner (or merchant) with a variable-condition page — e.g. merchant page "gold ≥ 10" gives a discount/freebie — demonstrating data-first branching; `pnpm validate` green. |
| **Files touched** | `packages/core/src/schema/map.ts`, `packages/core/src/interpreter/interpreter.ts`, `packages/core/tests/interpreter/interpreter.test.ts` (or a focused condition test), `packages/core/tests/schema/map.test.ts`, `samples/maps/town-square.map.json`, this task doc |
| **Acceptance criteria** | Every op covered by unit tests (true + false); existing switch-condition behavior unchanged (current tests green, sample data untouched); `validate` green; QA gate (build/typecheck/lint/format/doc:lint/test/validate) green. |
