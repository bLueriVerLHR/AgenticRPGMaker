# Task 16 — Dialogue choices: `showChoices` command + choice UI + variable feedback

| Field | Value |
|---|---|
| **Goal** | The player can answer dialogue prompts: an event-page `showChoices` command publishes a `choice` event (options + target variable); the runtime renders a selectable option list; the chosen index (or `-1` on cancel) is written to the variable; pages then branch on that variable via the task-15 variable conditions. A sample NPC demonstrates the full loop (question → answer → branch). |
| **Why** | Goal axis "增强可定制性（事件命令系统）" + "改进事件解释器/数据管线" + "以可玩样例作为验收基准". Interaction so far is one-way (NPC talks); choices are the core RPG interactivity that variable conditions (task 15) exist to serve — the loop "question → answer → branch on answer" is the foundation of quests and dialogue trees. |
| **Approach** | **Core (no schema change — command set is open):** 1. `events/game-events.ts`: `ChoiceEvent { variable: string; options: string[] }` + `GameEventMap["choice"]`. 2. `interpreter/commands.ts`: `ShowChoicesCommand` — cmd `"showChoices"`, args `[variable, ...options]` (≥2 options, else fail fast like the other built-ins); executes: record effect `{ kind: "choice", variable, options }` + `bus.emit("choice", ...)`; register in `builtInFactories`. The core only declares intent (never renders UI); the runtime answers by writing the variable. **Runtime (`map-scene.ts`):** 3. Subscribe to `choice`: set `pendingChoice = { variable, options, selected }`; render a DOM option list (reusing the dialogue-box styling; `data-testid="choice-box"`), highlighting the selected option. 4. While a choice is open, `update()` routes input to the choice: `consumeDirectionEdge()` up/down wraps the selection; `consumeConfirm()` writes `state.setVariable(variable, selected)` and closes; `consumeCancel()` writes `-1` and closes; movement/dialogue are frozen. 5. **Tests** (runtime): emit a choice on the bus, feed direction edge + confirm, assert the variable was written to the chosen index (and `-1` on cancel). **Sample:** 6. New `Riddle Keeper` NPC in town-square (variables seed `choice_riddle: -1`): the correct-answer branch (`choice_riddle eq 0` → +5 gold), the wrong-answer branch (`eq 1`), the walked-away fallback (`sw_asked_riddle` true — i.e. cancelled with `-1`), and the ask page last (condition null → `showText` question + `setSwitch sw_asked_riddle` + `showChoices("choice_riddle", "A clock.", "A coin.")`). **Page order matters (implementation note):** `selectPage` picks the FIRST page whose condition holds and a `null` condition always matches, so the branch pages must precede the ask page. `pnpm validate` green. **Docs:** note the page model: `showChoices` is an async UI — put it last in a page; the question text stays on screen while the choice is open (movement/dialogue input frozen) and is dismissed with one confirm after answering; the answer is read on the next interaction via variable conditions (a suspend/resume interpreter is future work). |
