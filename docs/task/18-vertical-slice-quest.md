# Task 18 — Vertical slice: "The Lost Shipment" playable quest (3 maps)

| Field | Value |
|---|---|
| **Goal** | A complete, winnable mini-quest authored data-first (versioned JSON only, `pnpm validate`-gated) that exercises every current engine capability in one playable loop: dialogue → choices → variable/switch branching → patrol behaviors → **map transfers (task 17 loader)** → cross-map state persistence → save/load. Winning: find the crate in the cave, return to the elder, collect the reward. |
| **Why** | The 2026-08-31 next-phase decision (`discussion/2026-08-31-next-phase-vertical-slice.md`): the owner chose a playable vertical slice as the next-phase acceptance baseline ("以可玩样例作为验收基准", D24) — real content is what exposes engine gaps (it already found the task-17 loader gap). No new ADR: this is content, not architecture; it builds inside ADR-008/D24 as-is. |
| **Approach** | **Maps (`samples/maps/`, tileset `tilesets/placeholder`, tile layers `ground` + `colliders`):** 1. `quest-village.map.json` (12×9, `map_quest_village`) — Elder Rowan (`evt_elder`): first talk explains the missing shipment and sets `sw_quest_started`; after `sw_crate_found`, rewards +25 gold and sets `sw_quest_done`. Guard Bren (`evt_gate_guard`) at the north road: flavor pages on `sw_quest_started`. Gate event `evt_village_gate` at the road's end: `transfer` → `map_quest_forest`. 2. `quest-forest.map.json` (14×10, `map_quest_forest`) — tree-collided winding road; Slime (`evt_slime`, rule-based patrol waypoints): talk → `showChoices` fight/flee → branch on `forest_fight`; Cave mouth `evt_cave_mouth`: `transfer` → `map_quest_cave`; return transfer `evt_forest_south` → village. 3. `quest-cave.map.json` (12×9, `map_quest_cave`) — Crate (`evt_crate`, trigger, no sprite): "The missing shipment!" + `setSwitch sw_crate_found`; Bat (`evt_bat`, patrol) flavor; exit `evt_cave_exit` → forest. **State:** variables `gold`, `forest_fight: -1`; switches `sw_quest_started/sw_crate_found/sw_quest_done`. Cross-map state survives transfers because `createGame` reuses one `GameState` across scenes (game.ts transfer handler) and saves carry variables/switches/mapId. **Project:** 4. `samples/projects/lost-shipment.project.json` — `initialMap: map_quest_village`, maps list = the three quest maps; it intentionally sorts before `town-square.project.json`, so `build:www`'s `projectFiles[0]` ships the QUEST as the default www experience (town-square maps stay in the bundle; reachable via the `map` URL override). **Gates:** 5. `pnpm validate`; `pnpm build:www` ships the quest data; boot smoke via the built `www/` bundle is covered by the deploy verify script. |

A scripted end-to-end walk-through (transfer village→forest→cave→forest→village with state intact) is engine-level covered by the task-17 boot test + task-14 game tests. |
